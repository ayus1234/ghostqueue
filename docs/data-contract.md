# GhostQueue Canonical Data Contract

## 1. Overview

GhostQueue analyzes interaction lifecycles across diverse operational workflows (contact centers, healthcare triage, physical ticket queues, and digital onboarding). To accommodate heterogeneous datasets without requiring hard schema rigidity, the system maps source data into a canonical operational contract.

## 2. Supported Datasets

1. **Public Contact-Center Dataset**: Multi-queue telephony logs with queue tags, wait times, timestamps, and disposition statuses.
2. **Healthcare Call-Center Dataset**: Triage and emergency dispatch queue logs featuring priority metrics, arrival rates, and service bottlenecks.
3. **User-Provided CSV / JSON**: Custom operational datasets uploaded by users for ad-hoc private intelligence.
4. **Simulation-Generated Datasets**: Synthetic queue events generated by the What-if engine to evaluate structural intervention scenarios.

## 3. Canonical Schema Specification

| Logical Concept | Canonical Field | Type | Description | Mandatory |
| :--- | :--- | :--- | :--- | :--- |
| **Interaction ID** | `interaction_id` | `string` | Unique identifier for the customer, ticket, or call | Yes |
| **Timestamp** | `timestamp` | `ISO 8601 string` / `epoch` | Arrival or event timestamp | Yes |
| **Stage / Queue** | `stage` | `string` | The queue, department, or process stage | Yes |
| **Status / Disposition**| `status` | `string` | Outcome: `completed`, `abandoned`, `timeout`, `cancelled` | Yes |
| **Wait Time** | `wait_time` | `float` | Duration spent waiting prior to service or abandonment (sec) | Recommended |
| **Service Duration** | `service_time` | `float` | Duration of active handling if completed (sec) | Optional |
| **Capacity / Agents** | `agents_available`| `integer` | Active staff or capacity units during the interval | Optional |
| **Priority / Skill** | `priority` | `string` / `integer` | Routing priority or skill tier | Optional |

## 4. Journey Granularity & Feature Support

GhostQueue explicitly enforces analytical truth based on the granularity of the ingested dataset:

- **Event-Level / Session-Level Data**:
  - Contains chronological intermediate steps (e.g., entered queue -> hold music -> menu option -> abandoned).
  - **Capabilities**: Full Abandonment Analytics, Ghost Zones, and **Ghost Replay**.
- **Interaction-Level / Aggregate Data**:
  - Contains single-row summaries per interaction without discrete sub-event logs.
  - **Capabilities**: Full Abandonment Analytics, Ghost Zones, and What-if Simulator.
  - **Replay Behavior**: The UI must explicitly report that *Ghost Replay is unavailable for aggregate records* rather than fabricating synthetic intermediate hops.

## 5. Auto-Detection and Normalization Rules

1. **Status Mapping**: Any field resembling disposition, result, or call outcome is normalized into binary states:
   - Abandoned: `abandoned`, `hangup`, `dropped`, `cancelled`, `timeout`, `ghost`
   - Completed: `completed`, `answered`, `handled`, `resolved`, `success`
2. **Time Parsing**: Supports standard RFC 3339 / ISO 8601 strings, UNIX timestamps, and standard SQL datetime patterns (`YYYY-MM-DD HH:MM:SS`).
3. **Wait Time Inference**: If explicit wait times are missing, inferred from `service_start_time - queue_entry_time`.
